# Командная строка и потоки данных

Цель: уверенно ориентироваться в Linux и собирать команды в проверяемые конвейеры.

## Каталоги и оболочка

pwd показывает текущий каталог, cd меняет его в текущей оболочке, ls перечисляет записи. Абсолютный путь начинается с /, относительный вычисляется от текущего каталога. `.` означает текущий, `..` — родительский каталог. Команда cd — builtin: отдельный дочерний процесс не может изменить каталог своего родителя. Для возврата используй cd -; путь с пробелом заключай в кавычки. type и command -v помогают отличить alias, функцию, builtin и найденную через PATH программу.

## Аргументы и раскрытие

Оболочка обрабатывает кавычки, переменные и glob до запуска программы. `"$name"` сохраняет одно значение одним аргументом; без кавычек пробелы и шаблоны могут изменить число аргументов. Одинарные кавычки сохраняют буквальный текст. `*` не означает «все вообще»: скрытые файлы обычно не включаются. Имена могут содержать перевод строки, поэтому разбор вывода ls в скрипте ненадёжен. Для передачи имён используй аргументы либо find -print0 с обработчиком NUL.

## stdin, stdout и stderr

Дескриптор 0 — вход, 1 — обычный вывод, 2 — ошибки. `>` создаёт или обнуляет файл, `>>` дописывает, `<` подаёт файл на вход. Pipe передаёт stdout одной команды на stdin следующей; stderr сам по себе в него не попадает. Порядок перенаправлений важен: `command >all.log 2>&1` объединяет оба потока в файл, а `command 2>&1 >out.log` оставляет stderr на прежнем stdout. printf даёт предсказуемое форматирование без неоднозначностей echo.

## Код завершения

Успешная команда обычно возвращает 0, ошибка — ненулевой статус. `$?` относится к последней выполненной команде. В pipeline без pipefail обычно виден статус последней стадии, поэтому ранний сбой может потеряться. `&&` выполняет следующий шаг после успеха, `||` — после неуспеха; это управление выполнением, а не просто короткая запись if для любых сложных сценариев. Сначала проверь каждую стадию на маленьком входе, затем соединяй в конвейер.
