# Bash: функции, массивы и библиотеки

Цель: разделять сценарий на операции с ясным интерфейсом, не теряя аргументы и не смешивая данные со статусом.

## Интерфейс функции

Функция Bash получает позиционные аргументы собственным `$1`, `$2` и `"$@"`. Сначала проверь число аргументов и контракт значений. return задаёт код завершения, ограниченный диапазоном статуса, а не произвольное большое число и не текст. Строковый результат передавай через stdout; диагностику — через stderr. Командная подстановка получает stdout, поэтому отладочный printf туда может испортить машинный результат. Для передачи сложных данных можно выбрать явный файл, массив по согласованному интерфейсу либо другой язык.

`local` ограничивает переменную вызовом функции, но Bash использует динамическую область видимости: вложенная вызываемая функция может видеть локальные переменные вызывающей. Не строй скрытый API на случайно совпавших именах. Без local присваивание обычно меняет состояние текущего shell. Вызов в subshell или `$(...)` не возвращает изменения обычных переменных родителю; побочные эффекты должны быть явно оговорены.

## Массивы и границы элементов

Индексированный массив объявляй как `values=("first item" "second")`. `"${values[@]}"` передаёт каждый элемент отдельно, а `"${values[*]}"` формирует одну объединённую строку с выбранным разделителем. `${#values[@]}` даёт число заданных элементов; разреженные индексы означают, что это не всегда последний индекс плюс один. Для обхода индексов используй `"${!values[@]}"`. Ассоциативный массив связывает строковый ключ со значением; порядок обхода не обещан, поэтому для воспроизводимого отчёта сортируй ключи отдельно.

При чтении произвольного ввода не подставляй его без проверки в арифметические индексы или выражения. Пустой массив, пустой элемент и отсутствие значения — разные случаи. Проверяй поддержку нужной версии Bash, особенно если используешь ассоциативные массивы, nameref или mapfile. Скрипт с shebang Bash не следует запускать командой sh в надежде на тот же синтаксис.

## Рекурсия и библиотеки

Рекурсивная функция должна иметь базовый случай и уменьшать оставшуюся работу. Для shell глубокая рекурсия дорого стоит, а арифметика имеет машинные ограничения: обход больших деревьев удобнее доверить find или другой подходящей программе. Нельзя делать рекурсивное удаление по непроверенному пользовательскому пути.

`source ./library.sh` или `. ./library.sh` выполняет содержимое в текущем shell, а не только «подключает определения». Поэтому доверяй источнику, выбирай стабильный путь относительно самого сценария и избегай неожиданных действий на верхнем уровне библиотеки. Разделяй объявления функций и исполняемый main. Повторное source не должно дублировать изменения окружения. Для публичных функций используй понятный префикс, чтобы не переопределять чужие имена.
