# DAC файлов и каталогов, ACL и риски SUID

Цель: объяснять отказ доступа через правила объекта и всего пути, выдавая минимально достаточные права.

## Классы доступа

Обычный режим содержит rwx для владельца, группы и остальных. Для файла r означает чтение содержимого, w — изменение, x — возможность исполнения с учётом формата и остальных ограничений. Проверяется соответствующий класс: совпадение владельца не даёт «попробовать ещё права others». Числа r=4,w=2,x=1 образуют восьмеричный режим; 640 — чтение/запись владельцу, чтение группе, ничего остальным. chmod меняет режим, chown — владельца, chgrp — группу.

## Каталоги и путь

Для каталога r позволяет перечислять имена, x — искать известное имя/проходить путь, w вместе с необходимым поиском — изменять набор записей. Удаление файла регулируется прежде всего правами родительского каталога, а не writable-флагом самого файла. Sticky bit ограничивает удаление в общедоступном каталоге по дополнительным правилам владельцев. Даже читаемый файл недоступен, если отсутствует search permission на одном из родительских каталогов. Диагностика namei -l помогает увидеть весь путь.

## Создание и ACL

umask убирает права из запрошенного режима новых объектов; она не добавляет execute автоматически и не меняет уже созданные файлы. Для точечной выдачи пользователям/группам можно применять POSIX ACL. getfacl показывает записи и mask, которая может ограничить эффективные права именованных пользователей и группы. Default ACL каталога влияет на наследование новыми объектами. Проверяй фактические effective-права и создание нового файла, а не только текст команды setfacl.

## Особые биты и проверка SUID

SUID у подходящего исполняемого файла может менять effective UID при запуске, setgid — GID; setgid каталога помогает наследованию группы. Эти механизмы зависят от типа объекта и ограничений монтирования/среды. В курсе сохраняется исходное видео о SUID на скомпрометированном хосте, а наша практика направлена на инвентаризацию и устранение лишних привилегий в собственном стенде. Ищи неожиданные SUID-файлы, проверяй пакетное происхождение и изменения относительно эталона. Не включай SUID на оболочке для проверки «удобного root».
