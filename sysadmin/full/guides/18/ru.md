# Bash: перенаправления и собственные файловые дескрипторы

Цель: направлять данные и диагностику независимо, понимать порядок перенаправлений и управлять временем жизни открытого дескриптора.

## Три стандартных потока

Дескриптор 0 обычно соответствует stdin, 1 — stdout, 2 — stderr. Это соглашение процесса, а не обязательная связь с клавиатурой и экраном. Перенаправление `>file` открывает файл заново с усечением, `>>file` добавляет, `<file` подаёт вход. Диагностику отправляй `printf 'ошибка\n' >&2`, чтобы её можно было отделить от машинного результата. Программа, печатающая и ошибки, и данные в stdout, заставляет вызывающий код гадать о формате.

Pipeline соединяет stdout одной команды со stdin следующей, но stderr по умолчанию остаётся отдельно. В Bash `|&` также подключает stderr, что полезно для лога и опасно для чистого потока данных. Выбирай это намеренно. `/dev/null` принимает ненужный вывод, однако перенаправление ошибок туда может скрыть отказ важной операции.

## Почему порядок важен

Перенаправления выполняются слева направо. `command >all.log 2>&1` сначала связывает stdout с файлом, затем делает stderr копией этого назначения. В `command 2>&1 >out.log` stderr копирует прежний stdout и не переезжает вслед за последующим изменением stdout. `2>&1` не создаёт вечную символьную связь между номерами: оно дублирует текущее назначение.

Конструкция `>source source-processing` может обнулить источник ещё до начала чтения команды. Не редактируй файл через `filter file >file`. Пиши результат в отдельный проверенный временный файл, валидируй и затем меняй исходник согласованным способом. Для важных конфигов сохраняй права, владельца, метку безопасности и возможность отката, а не только байты.

## Открытые дескрипторы

`exec 3<input.txt` открывает дополнительный вход в текущем shell, `exec 4>output.txt` — выход. `read -r value <&3` и `printf '%s\n' "$value" >&4` используют их без переоткрытия файла на каждой итерации. `exec 3<&-` и `exec 4>&-` закрывают соответствующие дескрипторы. Без команды exec меняет окружение самого shell; с командой exec заменяет процесс — это два разных применения.

Не оставляй служебные дескрипторы неожиданно открытыми дочерним процессам и не переиспользуй номер, который уже нужен вызывающему окружению. Для библиотечного кода Bash может выделить номер через `exec {fd}<file`; поддержка зависит от версии. Here-document с закавыченным ограничителем сохраняет текст буквально, без подстановок внутри. Here-string добавляет завершающий newline, что важно для побайтовых протоколов.

<details><summary>Разбор</summary>
