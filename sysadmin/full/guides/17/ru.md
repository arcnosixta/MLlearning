# Bash: условия, циклы, аргументы и read

Цель: написать небольшой Bash-сценарий с проверяемыми входами, корректными кавычками и понятным кодом завершения.

## Как shell читает команду

Строка сценария проходит разбор и подстановки до запуска команды. Незакавыченная переменная может подвергнуться разделению на слова и раскрытию glob-шаблонов. Поэтому имя файла передавай как `"$file"`, а все позиционные аргументы — через `"$@"`, сохраняя их границы. `$*` и `$@` внутри двойных кавычек ведут себя по-разному. Одинарные кавычки сохраняют буквальный текст; двойные разрешают подстановку переменных и команд. Не используй eval для обработки обычного пользовательского значения: данные не должны превращаться в shell-код.

Присваивание записывается без пробелов вокруг знака равенства: `name=value`. Командная подстановка `result=$(command)` получает stdout и удаляет завершающие переводы строк. Код завершения команды доступен в `$?`, но следующая команда заменит его. Успех означает 0, отказ — ненулевой код; это не возвращаемое строковое значение функции.

## Условия и повторение

if проверяет статус команды. В Bash `[[ ... ]]` удобно проверяет строки и шаблоны без части проблем word splitting, а `(( ... ))` — арифметическое условие. Строковое `>` и числовое `-gt`/арифметическое сравнение решают разные задачи. Пустое или нечисловое значение сначала валидируй. Для выбора ветки по фиксированным словам подходит case. Цикл `for arg in "$@"` сохраняет каждый аргумент, while повторяется по условию, until — до успеха условия.

Проверяй границы: ноль записей, последнюю строку и отсутствие ожидаемого поля. Не разбирай вывод ls циклом по словам: пробелы и переводы строк в именах разрушат соответствие. Для файлов используй glob с правильной политикой пустого совпадения или find с нулевым разделителем.

## Надёжное чтение

`IFS= read -r line` сохраняет пробелы по краям и не трактует обратный слеш как escape. Для простого учебного формата с разделителем можно задать `IFS=,`, но это не полноценный CSV-парсер: quoted fields и переносы строк требуют соответствующего инструмента. `read -p` удобно для интерактивного запроса, однако скрипт должен иметь режим без диалога для автоматизации. `read -s` скрывает ввод терминала, но не делает секрет безопасным для последующего логирования.

Цикл справа от pipeline в обычном Bash часто выполняется в subshell; обновлённый внутри счётчик может не сохраниться снаружи. Чтение через перенаправление файла или process substitution оставляет цикл в текущем shell. Политику EOF определи явно: `while IFS= read -r line || [[ -n $line ]]` обрабатывает последнюю строку без завершающего newline.
