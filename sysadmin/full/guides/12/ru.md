# Развёртывание приложений: Traffic Monitor и NetBox

Цель: разложить установку прикладной системы на зависимости, проверяемые этапы и восстановление.

## От пакета к работающей системе

Видео показывают прикладные развёртывания как сборку ранее освоенных навыков: сеть, диски, пользователи, БД, службы и доступ. Это не одна магическая команда. До начала определи версию продукта, поддерживаемую ОС, ресурсы, лицензирование, сетевые порты и место данных. Для IW Traffic Monitor используй документацию и дистрибутив поставщика своей версии: проприетарный пакет и лицензия не входят в наш курс. Сохраняй исходную демонстрацию, но не считай её старый установщик универсальным рецептом для новой ОС.

## Стек NetBox

NetBox хранит модель инфраструктуры, а не автоматически обнаруживает всю сеть сам по себе. Для установки нужны совместимые PostgreSQL, Redis и Python по таблице выбранного выпуска, само приложение, WSGI-сервер и HTTP reverse proxy. Проверь [официальный порядок установки](https://netboxlabs.com/docs/netbox/installation/). Не фиксируй версии зависимостей по памяти: они меняются между выпусками. Приложение запускай отдельным пользователем, конфигурацию с секретами не публикуй и не копируй в учебные ответы.

## Порядок установки и применение

Сначала проверь сеть, время, hostname и хранилище. Подготовь БД с отдельной ролью, Redis с нужной доступностью, затем окружение приложения. Выполни предусмотренные выпуском миграции и сборку статических файлов, создай административную учётную запись по официальной инструкции. После настройки менеджера службы проверь backend локально, затем reverse proxy и доступ клиента. Worker/очередь фоновых задач требуют своей проверки: успешная главная страница не доказывает работоспособность всех функций. Не открывай БД и Redis всему интернету ради упрощения установки.

## Приёмка и восстановление

Критерии приёмки должны включать вход, создание тестового объекта, чтение после перезапуска, фоновые операции и корректный HTTPS, если он задан. Сними журналы приложения, systemd и прокси для одного тестового запроса, не смешивая их роли. Backup включает БД, пользовательские файлы и нужную конфигурацию; snapshot без согласованности БД может оказаться непригодным. Восстанови копию на отдельной VM и проверь функцию, а не просто успешное распаковывание. Перед обновлением согласуй совместимость схемы и обратную миграцию либо возврат всей согласованной копии.
