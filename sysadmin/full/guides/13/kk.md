# SSH: қосылу, кілттер және қолжетімділікті шектеу

Мақсат: кілтпен қашықтан кіруді орнатып, өзгеріс кезінде қалпына келтіру жолын сақтау.

## Қосылу кезеңдері

ssh — клиент, sshd — сервер. Маршрут, тыңдайтын порт және аутентификацияны бөлек тексер. Серверде `ss -ltn`, клиентте `ssh -vv user@host` диагностика береді. Журналды жарияламай тұрып жеке мәліметті қарап шық.

known_hosts ішіндегі сервер кілті түйінді тануға арналған. Кілт өзгерсе, StrictHostKeyChecking өшірме: fingerprint-ті сервер консолінен тәуелсіз салыстыр. Пайдаланушы кілті басқа міндетті атқарады — нақты аккаунтқа кіру құқығын дәлелдейді.

## Кілт және құқықтар

Оқу клиентінде бөлек файлға `ssh-keygen -t ed25519` жаса. Жабық кілтті серверге көшірме; authorized_keys ішінде ашық кілт болады. Үй каталогы, .ssh және файл иесін, құқықтарын тексер. Бір файлдың рұқсаты дұрыс болса да, ата-аналық каталог қате болуы мүмкін. Agent forwarding мүмкіндігін себепсіз қоспа.

## Өзгерісті тексеру

Бөлек VM және консоль қолдан. Бастапқы конфигурацияны сақта, `sshd -t` тексеруін орында. Match және Include ережелерінің тиімді нәтижесін `sshd -T` арқылы қара. Ескі сеансты жаппай, жаңа сеанспен кілтті тексер. Содан кейін ғана парольдік жолды шекте. PasswordAuthentication барлық интерактивті PAM тәсілдерін жалғыз өзі сипаттамайды. Сәтсіздікте консольден бұрынғы файлға қайт.

## Практика

### 1. Жаңа кіру

Кілтпен екінші сеанс аш. Парольді өшіру алдында нені дәлелдейсің?

{{answer:1}}

<details><summary>Көмек және шешім</summary>

Консоль қолжетімді, sshd -t дұрыс, fingerprint сәйкес және жаңа кілтпен дұрыс аккаунтқа кіргенің расталуы тиіс. id нәтижесін тексер.
</details>

### 2. Кілт қабылданбады

chmod 777 қолданбай диагноз қой.

{{answer:2}}

<details><summary>Шешім</summary>

Аккаунтты, authorized_keys, иені, бүкіл жол құқықтарын, sshd тиімді параметрлерін және сервер журналын тексер. Нақты себепті түзет.
</details>

### 3. Сервер кілті
