# Пользователи, группы и минимальные полномочия sudo

Цель: выдавать ровно необходимые права и различать смену личности, среды и рабочего каталога.

## Идентичность процесса

Linux проверяет числовые UID/GID и дополнительные группы процесса, а не красивое имя учётной записи. id показывает текущую идентичность. /etc/passwd описывает локальные записи, защищённые данные аутентификации находятся отдельно; getent обращается к настроенным источникам NSS, включая внешние службы. После добавления в группу существующая сессия может не получить новый набор групп: проверь новую сессию. Служебная учётная запись нужна для изоляции сервиса, а не для повседневного интерактивного входа.

## su и sudo

su меняет пользователя в новой оболочке, варианты login shell по-разному строят среду. sudo запускает разрешённую команду по политике и сохраняет аудит вызова. Возможность выполнить `sudo command` не означает доступ к любой команде. Проверяй `sudo -l`. cd — builtin текущей оболочки, поэтому `sudo cd /root` не переносит текущий shell в /root. Если нужен доступ к конкретному файлу или операции, решай это разрешённой командой/группой, а не выдачей полной root-оболочки.

## Политика минимального доступа

Редактируй sudoers через visudo и проверяй синтаксис до закрытия действующей сессии. Правило должно описывать пользователя/группу, хост, runas, точный исполняемый файл и допустимые аргументы. Многие редакторы, интерпретаторы и утилиты с shell escape фактически дают широкие права; ограничение только имени программы не гарантирует узкую операцию. PATH, доступность файла скрипта на запись и управляемые пользователем конфиги тоже влияют на безопасность. Для администрирования сервиса лучше небольшой root-owned wrapper с проверкой аргументов, чем универсальная команда с wildcard.

## Жизненный цикл

При создании пользователя определи владельца учётной записи, срок, домашний каталог, shell и группы. При отключении проверь активные сессии, ключи, задания расписания, служебные зависимости и принадлежащие файлы. Удаление строки пользователя само по себе не отменяет уже работающий процесс. Не переиспользуй UID без анализа оставшихся данных. Проверяй доступ под целевой личностью и сохраняй журнал административных действий.
