# Адресация, маршрутизация и диагностика канала

Цель: находить точку сетевого отказа и проверять пропускную способность между известными узлами стенда.

## Интерфейс и подсеть

`ip -br link` показывает интерфейсы, `ip -br address` — адреса с префиксами. Адрес без правильного префикса не задаёт ожидаемую локальную подсеть. IPv4 /24 означает 24 бита сети; адреса одной сети могут обмениваться на канальном уровне при подходящей топологии. Соседство проверяется через ARP для IPv4 и NDP для IPv6; `ip neigh` помогает увидеть разрешение адресов. Link up не доказывает доступность удалённого сервиса.

## Выбор пути

Таблица маршрутов определяет next hop и интерфейс. Более специфичный префикс обычно выигрывает внутри выбранной таблицы, но policy routing может сначала выбрать другую таблицу по правилам. `ip route` показывает маршруты, `ip rule` — правила, `ip route get DEST` — решение для конкретного назначения с контекстом. Default route /0 подходит, когда нет более точного маршрута. Обратный путь так же важен, как прямой: сервер может получать пакет, но отправлять ответ в другой шлюз.

## Последовательность проверки

Начни с локального интерфейса/адреса, затем сосед/шлюз, маршрут, нужный порт и приложение. ping проверяет ICMP, но его запрет не доказывает отсутствие TCP-доступа. ss -lntup на сервере показывает слушающий сокет и адрес bind; сервис на 127.0.0.1 недоступен извне без прокси. Для имени проверь DNS отдельно от доступа по IP. tcpdump с узким фильтром на своём стенде помогает увидеть запрос/ответ, но захват может содержать чувствительные данные — сохраняй только необходимый тестовый трафик.

## Измерение канала

iperf3 измеряет транспорт между сервером и клиентом, а не скорость любой загрузки из интернета. Зафиксируй направление, число потоков, длительность, TCP/UDP и условия. UDP-проверке заранее задай допустимую скорость, чтобы не перегрузить стенд. RTT, потери и throughput измеряют разные свойства. MTU и Path MTU могут объяснять ситуацию, когда маленький ping проходит, а крупный обмен зависает. Сравни до/после при одном и том же тесте, не объявляй единственный максимум гарантированной ёмкостью.
