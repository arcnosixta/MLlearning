# Generics, ограничения типов и PECS

Цель: писать повторно используемый код, который компилятор защищает от смешения несовместимых данных.

## Параметризация

`Box<T>` описывает семейство типов: Box<String>, Box<Integer>. Тип-параметр сообщает, какие операции допустимы, и избавляет от ручных cast при чтении. Примитивы нельзя подставить напрямую — нужен Integer. Raw type Box отключает часть проверок и переносит ошибку на выполнение. Generic-метод объявляет `<T>` перед возвращаемым типом; параметр метода не обязательно связан с параметром класса. Типы и ограничения выводятся из аргументов, но не всегда так, как ожидает читатель.

## Инвариантность

List<Integer> не является List<Number>: иначе через ссылку List<Number> можно было бы добавить Double в список целых. Массивы ведут себя иначе: Number[] может ссылаться на Integer[], а неправильная запись вызовет ArrayStoreException. Generics стараются исключить такую ошибку при компиляции. Не используй raw type для обхода проверки: это разрушает гарантию для остального кода.

## Wildcard и PECS

`? extends Number` — неизвестный подтип Number. Из такого источника можно читать Number, но безопасно добавлять конкретное число нельзя. `? super Integer` допускает запись Integer, чтение гарантирует только Object. PECS: Producer Extends, Consumer Super. `List<?>` пригоден для чтения объектов неизвестного типа. Сам wildcard не делает список неизменяемым: например, clear может быть доступен. Для связи типов источника и назначения введи параметр T, а не два независимых wildcard.

## Bounds и стирание

`<T extends Number>` ограничивает операции API Number. Для нескольких ограничений указывается класс первым, затем интерфейсы через &. Во время выполнения параметры в основном стираются; `new T()`, `new T[10]` и `instanceof List<String>` недопустимы. Передай фабрику Supplier<T> или Class<T>, если нужен экземпляр. Статическое поле не может иметь тип-параметр экземпляра класса. Generic varargs требует осторожности: смешение массивов и стирания может загрязнить кучу. @SuppressWarnings не исправляет нарушение контракта.
