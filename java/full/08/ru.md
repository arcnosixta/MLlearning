# Интерфейсы, композиция, enum и record

Цель: отделять контракт от реализации и моделировать допустимые состояния типами.

## Интерфейсы

Интерфейс определяет доступное поведение. Класс реализует несколько интерфейсов, сохраняя единственного родителя-класс. Поля интерфейса не являются состоянием экземпляра: это public static final константы. Обычный абстрактный метод интерфейса public, поэтому реализация должна оставаться public. default-метод даёт поведение по умолчанию. При конфликте двух несвязанных default-реализаций класс обязан определить выбор явно; private-методы интерфейса помогают разделить внутренний код.

## Композиция и внедрение зависимости

Сервис получает Formatter через конструктор и вызывает его, не создавая конкретную реализацию внутри метода. Можно передать форматирование RU, ҚАЗ или тестовый вариант. Такой объект становится зависимостью, которую легко заменить. В отличие от наследования реализацию можно комбинировать без глубокой иерархии. Не допускай null-зависимость: проверь её при построении объекта. Интерфейс полезен там, где есть реальная вариативность поведения, а не автоматически для каждого класса.

## Перечисления

enum задаёт конечное множество значений, например NEW, PAID, CANCELLED. Это полноценный тип с полями, конструктором и методами. Константы сравниваются через ==. name возвращает программное имя, ordinal — позицию объявления; хранить ordinal в базе опасно: перестановка констант изменит смысл. Для внешних данных используй стабильный код. valueOf требует точного имени и выбрасывает исключение для неизвестного значения. EnumSet и EnumMap подходят для типизированных наборов состояний.

## Record и неизменяемые данные

record генерирует компонентные поля, конструктор, аксессоры, equals, hashCode и toString. Поля final, но неизменяемость поверхностная: List-компонент может ссылаться на изменяемый список. В компактном конструкторе проверь вход и сделай List.copyOf. Record удобен для значений и DTO, а не для сущностей с меняющейся идентичностью и жизненным циклом. Он не может наследовать произвольный класс, зато может реализовать интерфейсы. Не подменяй контракт данных одним удобством генерации кода.
