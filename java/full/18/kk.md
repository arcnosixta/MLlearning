# Орындау ағындары және жад моделі

Мақсат: қатар орындау мен ортақ деректің қауіпсіздігін ажырату.

## Ағын келісімі

Runnable тапсырманы, Thread орындау ағынын сипаттайды. start жаңа ағын ашады, run тікелей шақырылса ағымдағы ағын орындалады. Thread қайта іске қосылмайды. Жоспарлаушы ретті кепілдемейді. Демон ағыны JVM аяқталуын тоқтатпайды.

sleep мониторды босатпайды. join басқа ағынның аяқталуын күтеді. counter++ оқу, есептеу және жазудан тұрады; екі ағын жаңартуды жоғалтуы мүмкін. volatile көрінуді қамтамасыз етеді, бірақ ++ атомарлы емес. synchronized бір монитор арқылы келісілген қорғау береді. join аяқталған ағын өзгерістерінің көрінуіне кепіл береді.

interrupt — бірлескен тоқтату сигналы. InterruptedException ұстап әрі қарай бермесең, флагты қалпына келтіріп жұмысты аяқта. Ескі stop/suspend/resume қауіпті. wait/notify монитор ішінде шақырылады, шарт while ішінде тексеріледі.

## Практика

### 1. Санауыш

synchronized алып тастағанда кейде дұрыс нәтиже неге шығады?

{{answer:1}}

<details><summary>Шешім</summary>

Қате жоспарға тәуелді. Бір сәтті іске қосу дәлел емес. Ортақ монитор не AtomicInteger қолдан.
</details>

### 2. Тоқтату

interrupt сигналын қабылдайтын цикл жаса.

{{answer:2}}

<details><summary>Шешім</summary>

Флагты тексер, InterruptedException кезінде қалпына келтіріп шық. Ресурсты finally ішінде жап.
</details>
