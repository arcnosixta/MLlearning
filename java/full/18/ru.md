# Потоки выполнения и модель памяти

Цель: отличать параллельное выполнение от безопасной совместной работы с данными.

## Thread и Runnable

Runnable описывает задачу без результата, Thread — отдельный поток выполнения. start запускает новый поток и затем вызывает run; прямой вызов run выполняется в текущем потоке. Один Thread нельзя запустить повторно. Планировщик не гарантирует порядок вывода или справедливость. Приоритет — подсказка, а не механизм правильности. Потоки-демоны не удерживают JVM от завершения, поэтому не поручай им единственную копию важного сохранения.

## Жизненный цикл

Thread.State различает NEW, RUNNABLE, BLOCKED, WAITING, TIMED_WAITING, TERMINATED. RUNNABLE не означает, что поток прямо сейчас занимает процессор. sleep приостанавливает текущий поток, но не освобождает монитор. join ждёт завершения другого потока. Вывод отладочного лога может менять взаимное расписание: исчезновение ошибки при println не доказывает исправление.

## Гонка, видимость и атомарность

`counter++` состоит из чтения, вычисления и записи. Два потока могут прочитать одно значение и потерять одно увеличение. volatile обеспечивает видимость и порядок определённых операций, но не делает ++ атомарным. synchronized использует монитор: одновременно защищённый участок выполняет один владелец этого монитора. Все обращения к общему инварианту должны применять согласованную защиту. При успешном join действия завершившегося потока видимы ожидающему; это отношение happens-before, а не случайный эффект задержки.

## Кооперативная отмена

interrupt подаёт сигнал, а не принудительно убивает поток. Блокирующие методы могут выбросить InterruptedException и сбросить флаг; если не передаёшь исключение выше, обычно восстанови флаг через currentThread().interrupt() и закончи работу. Цикл вычисления должен периодически проверять isInterrupted. Thread.stop/suspend/resume из старых материалов не используй: они могут нарушить инварианты и привести к зависанию. wait/notify вызываются при владении монитором; условие ожидания проверяют в while из-за повторных проверок и возможных ложных пробуждений.
