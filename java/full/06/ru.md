# Классы, конструкторы и инкапсуляция

Цель: создавать объекты, которые сохраняют корректное состояние после любой публичной операции.

## Состояние и поведение

Класс описывает тип, объект — конкретный экземпляр. Поля хранят состояние, методы выполняют операции. Два объекта одного класса имеют независимые поля экземпляра; static-поле принадлежит классу. Ссылка может указывать на объект или быть null. Создание через new выделяет объект и вызывает конструктор. Сборщик мусора освобождает недостижимые объекты, но не заменяет закрытие файлов и соединений.

## Конструкторы и инициализация

Конструктор не имеет возвращаемого типа, даже void. Как только объявлен собственный конструктор, автоматический конструктор без параметров не добавляется. this ссылается на текущий объект, `this(...)` делегирует другому конструктору и в Java 17 должен стоять первым. Инициализаторы полей экземпляра выполняются перед телом конструктора после построения родительской части. Не вызывай переопределяемые методы из конструктора: дочерний объект ещё может быть не готов.

## Инвариант объекта

Инкапсуляция — защита правил, а не просто создание getter/setter для каждого поля. Для кошелька баланс неотрицателен. Конструктор проверяет начальное значение, метод списания проверяет сумму и остаток до изменения. Публичный setter баланса обошёл бы смысл операции. private ограничивает доступ, package-private помогает общаться классам одного пакета, protected связан с наследованием. Успешный вызов должен сохранять инвариант; неуспешный — не оставлять частично изменённый объект.

## final и неизменяемость

final-поле присваивается один раз, но объект по ссылке может оставаться изменяемым. Для неизменяемого класса закрой поля, исключи изменяющие методы, скопируй изменяемые входы и не отдавай внутренние массивы. Геттер, возвращающий исходный список, разрушает защиту. Отдельно различай неизменяемую копию и неизменяемое представление, которое отражает изменения исходной коллекции. Статические счётчики и кеши усложняют независимость тестов.
