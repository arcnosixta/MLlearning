# Тестирование, Log4j2, TestNG, сборка и итоговый проект

Цель: превратить набор классов в воспроизводимо собираемое приложение с проверяемыми требованиями.

## Проверки поведения

Тест проверяет наблюдаемый контракт, а не повторяет строку реализации. Разделяй arrange, act, assert: подготовь вход, вызови операцию, сравни с ожидаемым результатом. Проверь обычный случай, границы и отказ. Для среднего нужны пустой набор, одна оценка, дробный результат и недопустимая оценка. Пустое среднее — отсутствие, а не ноль. Unit-тест не требует сети/БД; интеграционный проверяет реальное взаимодействие. Фиксируй часы и данные, не заставляй тест ждать случайный sleep.

## TestNG

TestNG — внешняя библиотека, её @Test не является Java assert. Assert-проверки выполняются независимо от флага -ea. @DataProvider задаёт таблицу входов и результатов, @BeforeMethod готовит независимое состояние, @AfterMethod освобождает его. expectedExceptions проверяет тип отказа; если исключение может прийти от подготовки, сузь область проверки через expectThrows. Группы разделяют уровни тестов. Параллельный запуск требует независимых fixtures: общее изменяемое поле класса может стать гонкой. Не делай один тест обязательной подготовкой другого без явной необходимости.

## Log4j2

Logging API и реализация различаются. Приложению с Log4j2 обычно нужны log4j-api и log4j-core согласованных версий; BOM помогает их выровнять. Logger получает события, фильтры/уровни отбирают их, Appender направляет вывод, Layout задаёт формат. Используй параметризованное сообщение `logger.info("students={}", count)`, а не сборку строки заранее. Ошибку логируй с объектом exception, сохраняя stack trace. Не записывай пароли, токены и полный персональный ввод. Повторное логирование одной ошибки на каждом слое засоряет диагностику. Настрой ротацию файлов и политику хранения.

## Сборка и структура

Maven pom.xml описывает координаты, зависимости, плагины и release=17. Исходники лежат в src/main/java, тесты в src/test/java, ресурсы отдельно. `mvn test` компилирует и проверяет, `mvn package` собирает артефакт. Один jar не обязательно содержит зависимости: для запуска укажи classpath или настрой сборку приложения. Без Maven JDK-пример запускается обычными javac/java. Следи за воспроизводимыми версиями; папки target и class-файлы не должны попадать в исходный репозиторий.

## Итоговый проект: журнал успеваемости

Раздели модель Student/Grade, сервис Gradebook, интерфейс GradeRepository, файловое или JDBC-хранилище и консольный UI. Функции: добавить студента с уникальным ID, назначить оценку 0–100, получить среднее по группе, экспортировать отчёт. Ошибочный импорт не должен частично менять журнал. Сохраняй UTF-8 и явный формат дат. Дополнительно подключи Swing-вид, HTTP-источник или XML-экспорт через отдельный адаптер. Не включай все технологии одновременно без цели.
