# Сети: TCP, UDP, HTTP и серверные приложения

Цель: различать транспорт и прикладной протокол, задавать границы сообщения и обрабатывать сетевые отказы.

## Адреса и протоколы

IP задаёт сетевой адрес, порт — конечную точку приложения, DNS связывает имя с адресами. URI описывает ресурс, URL добавляет схему доступа. В модели TCP/IP отделяй канальный, сетевой, транспортный и прикладной уровни; OSI — более детальная учебная модель. Частная сеть и VPN меняют связность, но не гарантируют доверие ко всем приложениям внутри. TCP передаёт упорядоченный поток байтов без границ сообщений; UDP передаёт датаграммы, которые могут потеряться, повториться или прийти не по порядку.

## Сокетный обмен

ServerSocket слушает порт, accept возвращает Socket соединения. Клиент соединяется с адресом и портом. Для протокола выбери framing: строка с ограниченной длиной, длина+байты или другой однозначный формат. Один read не равен одному сообщению. Обе стороны, ожидающие read до записи, могут зависнуть. Установи connect/read таймауты, задавай UTF-8, делай flush там, где протокол ждёт ответ. Для многих клиентов используй ограниченный пул, а не неограниченное создание потоков. UDP через DatagramSocket требует собственного контроля идентификаторов, повторов и допустимого размера сообщения.

## HTTP и безопасность передачи

HTTP запрос содержит метод, путь, заголовки и тело; ответ — статус, заголовки и тело. GET получает представление, POST часто создаёт действие, PUT имеет идемпотентную семантику замены. 2xx — успех, 4xx — проблема запроса, 5xx — ошибка сервера. Идемпотентность означает одинаковый смысл повторного запроса, а не одинаковый текст ответа. HTTPS использует TLS: не отключай проверку сертификата ради устранения ошибки. SSL из старых материалов — историческое название; конкретную поддержку протоколов определяет среда.

## Java HttpClient и архитектура

Java 17 HttpClient входит в JDK. Построй URI, HttpRequest с таймаутом, отправь через send или sendAsync, явно проверь statusCode. Код 404 сам по себе не обязан выбросить исключение. Сетевой повтор допустим только с учётом идемпотентности, общего срока и ограничения числа попыток. REST — архитектурный стиль, SOAP — XML-протокол сообщений, RPC — модель вызова удалённой операции. Servlet исполняется контейнером; Servlet API, JavaMail/Jakarta Mail и почтовый сервер не входят в обычный JDK. Для HTTP-сервера на Servlet нужны зависимости и контейнер, для почты — SMTP/IMAP настройки и учётные данные из конфигурации, не исходника.
