# Файлы, потоки ввода/вывода, NIO и сериализация

Цель: выбирать формат хранения, правильно закрывать ресурсы и отличать текст от бинарных данных.

## Байтовые и символьные потоки

InputStream/OutputStream передают байты; Reader/Writer — символы. InputStreamReader декодирует байты с указанной кодировкой. Буферизация уменьшает число обращений к источнику. read возвращает -1 при конце; ноль является допустимым байтом или символом. При чтении в массив обрабатывай ровно возвращённое число элементов, а не весь буфер. DataInputStream/DataOutputStream читают и пишут примитивы в согласованном порядке: файл не хранит названия полей. PrintWriter может скрывать IOException в состоянии ошибки, поэтому учитывай checkError.

## Path, Files и NIO

Path описывает путь, Files выполняет операции. Относительный путь разрешается от рабочей директории процесса, а не от исходника. Для небольшого текста подходят readString/writeString с UTF-8; большие файлы читай потоково. Files.lines/list/walk возвращают закрываемые потоки. Files.exists не гарантирует успех следующего открытия: файл мог измениться. Обрабатывай ошибку самой операции. normalize устраняет синтаксические сегменты, но не проверяет символические ссылки; для пользовательских путей проверяй границу разрешённого каталога по реальной политике приложения.

## Каналы и буферы

NIO Channel передаёт данные через Buffer. position — следующая позиция, limit — предел доступных данных, capacity — вместимость. После записи в ByteBuffer вызови flip перед чтением: limit станет прежней position, position — нулём. clear подготавливает буфер к новой записи, но не стирает содержимое. Канал может прочитать или записать меньше запрошенного; для полной операции нужен цикл. NIO.2 добавляет современную файловую систему; наличие слова NIO не делает любую операцию неблокирующей.

## Сериализация и архивы

Serializable сохраняет граф состояния объектов; static-поля не входят в состояние экземпляра, transient исключает поле из стандартной сериализации. serialVersionUID участвует в совместимости классов, но не решает миграцию смысла данных. Не десериализуй недоверенный поток без строгой политики: восстановление классов может выполнять опасную логику. Для обмена часто лучше явный JSON/XML/CSV-контракт. XMLEncoder/XMLDecoder — отдельный JavaBeans-механизм, тоже не безопасный универсальный парсер произвольного XML. ZIP объединяет записи, GZIP сжимает поток; при распаковке имена записей должны оставаться внутри целевой папки.

## Scanner и надёжная запись

Scanner удобен для токенов, но nextInt оставляет перевод строки перед nextLine. Выбирай единый способ чтения, задавай Locale для дробных чисел. Не закрывай System.in до окончания работы всего приложения. Для обновления важного файла сначала запиши временный файл рядом, закрой и затем перенеси на место; ATOMIC_MOVE зависит от файловой системы, а его неподдерживаемость нужно обработать. Для учебного примера ниже используется временный каталог и cleanup в finally.
