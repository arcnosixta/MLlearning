# JDBC, SQL, транзакции и DAO

Цель: выполнить параметризованный запрос, определить границу транзакции и отделить хранение от бизнес-логики.

## API и драйвер

JDBC — стандартный Java API, а не встроенная база данных. Connection представляет сеанс, PreparedStatement — подготовленную команду, ResultSet — курсор результата. Для конкретной СУБД нужен совместимый JDBC-драйвер в classpath и доступный JDBC URL. DataSource отделяет получение соединений от клиентского кода и может работать с пулом; DriverManager удобен в маленькой лабораторной. Современный драйвер обычно регистрируется через service-provider механизм; старые примеры Class.forName не являются обязательной частью каждого подключения.

## SQL и параметры

Таблица задаёт столбцы и ограничения, primary key — идентификатор, foreign key — связь. SELECT читает, INSERT/UPDATE/DELETE меняют данные. executeQuery возвращает ResultSet, executeUpdate — количество изменённых строк. Позиции параметров и столбцов начинаются с 1. Используй `WHERE id = ?` и setLong: конкатенация пользовательского текста меняет смысл SQL и открывает инъекцию. Параметры подставляют значения, не имена таблиц или ASC/DESC: динамическую структуру выбирай из разрешённого набора. SQL NULL не равен Java нулю; после getInt используй wasNull либо подходящий getObject.

## Транзакция

По умолчанию autoCommit обычно включён: команды фиксируются отдельно. Для перевода между счетами выключи autoCommit, выполни оба обновления, проверь число строк, затем commit. При SQLException сделай rollback и передай исходную причину выше. Если rollback тоже сломался, добавь его ошибку как suppressed. Не возвращай соединение в пул с открытой транзакцией. Savepoint позволяет откатить часть работы, но не заменяет общую границу. Уровни изоляции управляют наблюдаемыми аномалиями; конкретное поведение и поддержка зависят от СУБД.

## DAO и метаданные

DAO преобразует строки в объекты и скрывает SQL. Сервис определяет, какие действия должны быть одной транзакцией; отдельный commit в каждом DAO разрушил бы общую атомарность. ResultSet.next переводит курсор на строку, сначала он стоит до первой. Закрывай ResultSet, statement и connection через try-with-resources. DatabaseMetaData описывает возможности базы, ResultSetMetaData — столбцы ответа; CallableStatement вызывает хранимые процедуры по контракту конкретной СУБД. Batch уменьшает число сетевых обходов, но частичный отказ требует выбранной политики транзакции.
