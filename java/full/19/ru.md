# Executors, Future и средства concurrency

Цель: управлять задачами, ограничивать параллелизм и выбирать готовую синхронизацию вместо самодельных протоколов.

## Пул задач

Executor отделяет задачу от механизма выполнения. ExecutorService принимает Runnable и Callable<T>; submit возвращает Future. Callable может вернуть значение и выбросить проверяемое исключение. Future.get ждёт результат, ExecutionException оборачивает сбой задачи, get(timeout,unit) ограничивает ожидание, но сам по себе не отменяет вычисление. cancel(true) запрашивает прерывание — задача должна сотрудничать. В Java 17 ExecutorService не является ресурсом try-with-resources: заверши его через shutdown в finally, при необходимости awaitTermination и shutdownNow.

## Нагрузка и планирование

Число потоков, размер очереди и политика отказа определяют поведение при перегрузке. Executors.newFixedThreadPool ограничивает потоки, но использует очередь без фиксированного небольшого предела; для управляемой нагрузки настрой ThreadPoolExecutor с ограниченной очередью. ScheduledExecutorService заменяет многие сценарии Timer: fixedRate задаёт расписание по плановым началам, fixedDelay — паузу после завершения. Необработанное исключение в периодической задаче может прекратить её повторения. ForkJoinPool подходит для рекурсивного деления вычислений; блокирующий ввод требует отдельного внимания.

## Готовые примитивы

AtomicInteger даёт атомарный incrementAndGet, но несколько полей вместе требуют общего протокола. ReentrantLock позволяет tryLock и прерываемое ожидание; unlock ставь в finally после успешного lock. Semaphore ограничивает одновременно занятые ресурсы. CountDownLatch — одноразовое ожидание заданного числа событий, CyclicBarrier — повторяемая встреча участников. BlockingQueue с put/take реализует producer-consumer с обратным давлением; заранее продумай сигнал завершения и отмену.

## Concurrent-коллекции и CompletableFuture

ConcurrentHashMap обеспечивает конкурентные операции; для обновления используй merge/compute, а не get+put. Итерация обычно слабосогласованна, а не снимок всех данных. CopyOnWriteArrayList подходит, когда чтений значительно больше записей: каждое изменение копирует массив. CompletableFuture строит зависимости: thenApply преобразует значение, thenCompose разворачивает будущую задачу, thenCombine соединяет результаты. Async-варианты без явного executor используют свои правила выполнения, часто общий пул; не блокируй его случайно. exceptionally/handle задают политику ошибки, а не повод заменить любой отказ нулём.
