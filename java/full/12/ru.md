# Исключения, ошибки и управление ресурсами

Цель: проектировать понятные отказы и сохранять исходную причину ошибки.

## Иерархия и контракт

Throwable имеет ветви Error и Exception. RuntimeException и её наследники непроверяемые; остальные Exception обычно требуют catch либо объявления throws. Error описывает серьёзные проблемы среды; ловить всё через Throwable для продолжения работы опасно. throw создаёт переход управления с объектом исключения, throws объявляет возможность отказа. IllegalArgumentException сообщает о нарушенном предусловии; IOException — о неудаче ввода/вывода. Исключение должно нести смысл операции и необходимые сведения без секретов.

## Перехват и распространение

catch проверяются сверху вниз: конкретный тип должен стоять перед общим. Multi-catch объединяет несвязанные типы с одинаковой обработкой. Лови ошибку там, где можно восстановиться или перевести её в понятный ответ. Пустой catch скрывает потерю данных. При преобразовании исключения передавай cause в конструктор нового; иначе stack trace потеряет исходную причину. Переопределённый метод не может расширить проверяемые исключения сверх контракта родителя.

## finally и ресурсы

finally выполняет завершающие действия при обычном выходе и исключении, но не гарантируется при принудительном завершении процесса. return или новое исключение из finally могут скрыть исходный результат. try-with-resources закрывает AutoCloseable в обратном порядке объявления. Если тело и close выбросили исключения, исходное остаётся основным, ошибки закрытия доступны через getSuppressed. Поток, соединение и ResultSet закрывай по времени жизни операции, а не через GC.

## Собственные исключения и assert

Выделяй собственный тип, если вызывающий код должен отличать этот отказ. Не создавай десятки типов без сценария обработки. Для отсутствующего значения может подойти Optional; для частых нормальных развилок исключение обычно избыточно. assert — проверка внутренних предположений, выключенная по умолчанию; `java -ea Main` включает её. Валидацию пользовательского ввода нельзя строить на assert. При сбое статической инициализации тип может остаться непригодным к использованию в данном загрузчике; повторение вызова не равно чистому перезапуску.
