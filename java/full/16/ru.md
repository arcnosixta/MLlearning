# Stream API, коллекторы и Optional

Цель: описывать обработку данных последовательностью преобразований без скрытого общего состояния.

## Конвейер

Stream — одноразовый конвейер, а не контейнер. Источник может быть коллекцией, диапазоном, файлом или генератором. Промежуточные filter, map, flatMap, distinct, sorted, limit возвращают новый этап и обычно ленивы. Терминальные toList, collect, reduce, count, anyMatch запускают вычисление. Повторно использовать тот же stream после завершения нельзя. Для повторной обработки создавай новый из источника. Бесконечному источнику нужен предел до операций, которые ждут весь вход.

## Преобразования и порядок

map возвращает один результат на элемент, flatMap разворачивает вложенные потоки. filter меняет число элементов. sorted требует накопить данные и использует Comparator. distinct опирается на equals/hashCode. limit ограничивает число результатов, а не обязательно число прочитанных элементов во всех конвейерах. Encounter order зависит от источника и операций. peek предназначен для наблюдения, но не для обязательного бизнес-эффекта: оптимизации могут пропустить выполнение некоторых стадий.

## Сведение

reduce объединяет значения ассоциативной операцией и корректным нейтральным элементом. Для суммы нейтрально 0, для произведения 1. Вычитание неассоциативно и не даёт устойчивого параллельного reduce. Collectors.groupingBy строит группы, partitioningBy делит по boolean, mapping преобразует значения внутри группы, joining объединяет строки. Для toMap укажи политику дубликатов ключей; иначе конфликт вызывает исключение. Java 17 Stream.toList возвращает неизменяемый список; Collectors.toList не обещает конкретной реализации и изменяемости.

## Optional и параллельность

findFirst, min и max могут вернуть Optional. Используй map, flatMap, orElseGet и orElseThrow вместо непроверенного get. orElse вычисляет аргумент заранее, orElseGet вызывает поставщик только при отсутствии значения. Не представляй Optional как коллекцию с несколькими элементами. parallel не гарантирует ускорение: накладные расходы, блокировки и малые данные могут ухудшить результат. Функции должны быть независимыми и не менять источник; сбор в общий ArrayList через forEach небезопасен. Stream из Files.lines требует закрытия.
