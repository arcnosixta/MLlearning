# Строки, Unicode, regex и кодирование

Цель: обрабатывать текст без смешения символов, байтов и ссылочного равенства.

## String и Unicode

String неизменяем: trim, replace и toUpperCase возвращают результат, не меняя исходную строку. equals сравнивает содержимое, == — ссылки. length считает UTF-16 единицы, поэтому некоторые символы занимают две позиции. codePoints работает с кодовыми точками, но пользовательский видимый символ может состоять из нескольких точек. substring использует границу конца, не включённую в результат; проверь индексы. Нормализация Unicode может потребоваться для канонически эквивалентных записей. Не применяй её без понимания доменного правила.

## Эффективная сборка текста

Повторная конкатенация в цикле может создавать множество промежуточных строк. StringBuilder удобен для изменяемого буфера в одном потоке; StringBuffer синхронизирует отдельные операции, но не делает произвольный составной алгоритм атомарным. String.join и joining выражают намерение добавить разделитель. Форматирование задаёт представление, а не способ хранения числа. Locale.ROOT подходит для технических идентификаторов; пользовательский текст форматируй по выбранной локали.

## Регулярные выражения

Pattern — скомпилированное выражение, Matcher — состояние поиска по входу. matches требует совпадения всей строки; find ищет очередной фрагмент. В Java-литерале обратный слеш экранируется дважды: regex `\d+` записывается как `"\\d+"`. Группы извлекают части, квантификаторы задают повторения. Для поиска буквального пользовательского текста используй Pattern.quote. В строке замены $ и обратный слеш имеют особый смысл — при необходимости Matcher.quoteReplacement. Сложные вложенные повторения могут резко увеличить время обработки.

## Байты и безопасность смысла

Преобразовывай строку в байты с явной StandardCharsets.UTF_8 и декодируй тем же способом. Base64 позволяет передавать байты текстом, но не скрывает содержание. Хеш SHA-256 даёт отпечаток, а не обратимое шифрование; для паролей обычного быстрого хеша недостаточно. Шифрование требует алгоритма, ключа, режима и корректного управления nonce; не сочиняй собственную схему. Для этой главы достаточно понимать различия и не называть кодирование защитой секрета.
